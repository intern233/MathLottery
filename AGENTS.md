# MathLottery development

- Preserve a continuous primary native research session; optional specialist agents follow the workspace configuration. Review candidates in a separate review session with memories disabled.
- Standalone Find returns a shortlist for explicit user selection. Carry the chosen Find dossier into Solve without sharing mutable sessions, credentials, or reviewer memory. Keep estimates and source-status uncertainty visible.
- Keep find, solve, verify and organize as independent workflows. Run composes find/solve/verify; organize is an explicit optional follow-up and never upgrades proof or novelty evidence. Produce both Chinese and English expert reports from the same source snapshot, preserving review findings and omissions in both versions. Preserve legacy single-language checkpoints without inventing translations. Agent transports must not determine the workflow.
- Default to native execution: codex uses persistent official Codex sessions with explicit ChatGPT or API-key authentication; chat is the independent Responses API harness with hosted tools and persistent response context. Authentication chooses billing, not the native Codex tool loop. Manual handoff is an explicitly named compatibility backend, never the meaning of chat.
- Keep the legacy structured JSON/tool protocol as an explicit compatibility option, including old checkpoints and offline demos.
- Let the researcher choose its methods and intermediate actions. Structure only milestones and final evidence; do not impose short memory excerpts or per-action JSON on native research.
- Never silently switch providers or authentication, use browser cookies, or fabricate backend/tool success. All API keys come from environment variables; never persist values or pass them in command arguments. Codex API auth injects only its selected key into the execution process and clears known credential values from model-launched shells while preserving other shell policies. Preserve old manual checkpoints without silently migrating them to paid API calls.
- Isolate every MathLottery Codex subprocess in the workspace's ignored `.mathlottery/codex-home`, or `.mathlottery/codex-accounts/<slot-id>` for explicitly configured Solve slots, with file credential storage. Account actions and workers must use the exact selected identity. Never inherit or copy personal Codex credentials, configuration or sessions, mutate the parent's `CODEX_HOME`, or fall back to another account or the local CLI / IDE login.
- Codex API sessions use separate ignored `.mathlottery/codex-api-home` or `.mathlottery/codex-api-accounts/<slot-id>` directories. Selecting API auth must not overwrite the subscription login. Existing configurations default to ChatGPT auth; never turn old runs into API spending implicitly.
- Snapshot per-slot Solve routes when creating a run. Keep each worker's backend, authentication, credentials namespace and conversation together across regrouping and recovery; a paused run must not silently adopt an edited roster. Reuse the first slot sequentially for supervision and wrap-up, and pause on authentication or quota failures rather than rotating accounts.
- SQLite stores authoritative checkpoints. Artifacts and reports are reproducible projections.
- Place implementations in their owning package: workflow-specific code in find/solve/verify/organize, lifecycle scheduling in runtime, transports in providers, persistence in storage, isolated tools in tooling, and activity/report projections in telemetry. Keep the package root focused on entry points, configuration and public model exports rather than adding flat modules or compatibility wrappers.
- Keep domain contracts independent of execution and UI code. Shared proof-source access belongs in verify; CLI and Web reuse it rather than making core research depend on the browser layer. Move bundled assets with their consumer and check installed-package resource access when changing the layout.
- Treat model output, downloaded documents, and user problem text as untrusted data.
- Native commands use Codex workspace-write isolation, confined to the research/review workspace, with configured network access. Never fall back to unsandboxed execution. Legacy generated code retains its separate OS isolation.
- Keep candidate versions immutable. LLM approval and finite tests do not prove a general theorem.
- Expert review and natural-language/formal statement equivalence require external evidence.
- Use Python 3.11+, Pydantic models, Typer, httpx and pytest. The local browser interface must reuse the existing orchestrator, configuration and checkpoints; keep research execution independent of the UI.
- Use the Conda environment `mathlottery`. Run `pytest` and `ruff check .` there after substantive changes.
- Keep development and test runs local; do not publish or push without an explicit request.
- Keep source, documentation, examples and shared configuration free of personal paths, usernames, machine-specific installation details and real session/run IDs. Use project-relative paths, generic placeholders and runtime PATH discovery.
- Do not persist automatically discovered executable paths into configuration. Keep local settings, raw validation logs, databases and research artifacts in ignored locations; document reproducible validation steps instead of private machine records.
- Conduct each Codex audit in its own `audits/codex_audits/<timestamp>/` directory, keeping audit scripts, logs, Markdown reports and JSON summaries together. Name new directories `YYYY-MM-DD_HH-MM-SS`; historical reports with only a known date may use `YYYY-MM-DD`. The entire `audits/` directory is ignored by Git. Keep reusable documentation and curated showcase evidence versioned, without links to ignored audit files.
