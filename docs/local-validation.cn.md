# 验证方法与范围

[English](local-validation.md) | 简体中文

[项目介绍](../README.cn.md) · [安装与使用](usage.cn.md) · [结果样本](../showcase/README.cn.md)

本文提供可复用的检查步骤。具体机器路径、账户信息、真实会话标识和原始运行日志保留在被忽略的本地运行目录，不写入仓库文档。

## 自动化检查

在已安装开发依赖的 MathLottery 项目根目录运行：

```bash
conda activate mathlottery
pytest -q
ruff check .
python -m compileall -q src
python -m pip check
```

测试覆盖 native 与 structured 两种流程，包括：

- 精确会话续接、普通 Markdown 交接及跨模式反馈。
- find、solve、verify 的独立终止行为，以及 run 串联的完整流程。
- Chat Responses API 的请求体、服务端工具、连续上下文与独立审查上下文。
- 模型与 Max 参数的 Codex 会话续接、Chat Pro/standard 模式的独立传参，以及所有研究命令的命令行覆盖。
- Chat 后台响应的轮询、断线恢复、远端取消、真实用量字段及凭据不落盘。
- 独立审查、不确定结论的后续研究，以及部分成果通过后继续探索。
- 中断、限流、预算、回执恢复和孤儿子进程识别。
- 候选证明完整性、路径隔离及运行元数据。
- 离线数学实验、文献来源适配和可选形式验证工具的缺失处理。
- 本地浏览器 HTTP 边界、后台找题/求解/验真、候选完整性、临时配置、界面服务重启后的进程恢复与停止续接。
- 回环监听启动、Windows 保留端口、显式 WSL 直连，以及 Codex 账号状态、设备码登录和显式账号变更的边界。
- 提供方配置与模型目录、支持的思考选项、手填模型 ID、配置快照及有界的并发目录请求。

自动化后端测试使用明确标注的假 CLI 和 httpx.MockTransport，不消耗真实模型额度；隔离执行测试会运行真实子进程。手动交接测试仅覆盖 manual 兼容后端，不代表 chat 的调用方式。测试数量与耗时以本次命令输出为准。需要保存原始测试输出时，放入 .mathlottery/ 等被忽略的目录。

## 浏览器检查

分别运行 HTTP、账号、模型选择、证明附件及后台进程的相关测试：

```bash
pytest -q tests/test_web*.py tests/test_review_evidence.py
pytest -q tests/test_model_catalog*.py
```

测试使用模拟账号/目录响应、脚本化 Codex 程序和真实子进程，不调用模型。启动检查覆盖已有实例复用、端口和工作区冲突、Windows 保留的 TCP 端口范围、运行时项目定位、默认回环访问及显式 WSL 直连策略。

在两种语言下检查「提供方 → 模型 → 思考强度」、手动输入与目录加载失败。切换提供方/模型时应清除不兼容设置；上一提供方的迟到响应不得覆盖当前列表。新任务应保存所选设置，配置文件、历史任务和登录状态应保持不变。目录不得暴露接口凭据或账号信息，也不能把目录列出模型解释为保证可用。

检查 Find 候选列表与显式选题、跳过 Find 直接 Solve，以及对已保存候选进行 Verify。搜索和筛选历史、展开较早尝试后，轮询应保留这些选择与当前表单。两种语言都应分开展示任务运行结束、证明判断、原题覆盖和新颖性。窄屏布局也要覆盖。

使用 WSL 时，从真实 Windows 进程请求终端打印的 Windows `localhost` 地址，例如 Windows PowerShell 或 `curl.exe`。使用实际选择的端口，检查页面及 API 响应。仅在 Linux 内 HTTP 成功，不能确认 Windows 浏览器可访问。如果使用 `--wsl-direct`，单独检查该入口；它不能被隐式开启，也不应修改系统网络设置。

「MathLottery 账号」面板应检查未登录、等待授权、已登录、已取消和不可用状态，核对身份字段脱敏、官方链接校验，以及浏览器 localStorage 不保存凭据或设备码。确认账号错误不会阻塞研究历史，状态查询和普通登录不会启动研究或替换已有 MathLottery 登录。

核对 Codex 任务提交与续接都要求可用的 ChatGPT 登录，状态刷新失败后也不能沿用旧的登录显示启动任务。HTTP 预检查应在保存题目、创建任务或启动后台进程前，拒绝未登录、待授权、不可用、仅有 API Key 和不支持的账号类型。覆盖单次后端覆盖设置、已保存后端与当前默认配置不同的续接，以及页面显示后、提交前登录失效的情况。Chat API 任务不得查询 Codex 认证。提交被拒绝后，页面应保留错误并刷新账号状态，不自动重发请求。已有任务记录与个人 Codex 凭据应保持不变。

在研究或审查工作区创建模拟 `.lean`、`lean-toolchain` 和 `lakefile.toml` 文件，检查「结果」列表和纯文本下载。再在该工作区的 `proof/` 或 `formal/` 目录中创建 `.md`、`.txt`、`.json`、`.csv`、`.py` 文件；相同扩展名放在其他位置时应拒绝下载。覆盖 1 MB 读取限制、有限文件遍历、UTF-8 校验，以及隐藏目录、缓存、构建路径、目录穿越、软链接和硬链接的拒绝。模拟路径校验后、打开文件前父目录被换成软链接，确认仍不能读取。下载不得执行脚本、暴露任意任务文件或改变证明等级。源码存在不等于 Lean 检查通过、形式陈述等价或成果新颖；真实数学审计需另外记录准确的形式陈述、编译结果与信任假设。

证明源码交接应检查默认不选文件，轮询期间候选 ID 与校验值保持不变。候选已变化、源任务运行中、非法路径、重复选择或文件包超限时，必须在创建审查前拒绝。捕获后修改或删除原文件，再续接审查，检查点中的内容和哈希仍应保持不变。测试投影父目录软链接、HTTP 仅返回清单、Codex 文件交付，以及 Chat 实际收到提示内源码并遵守 128 KB 上限。中英文都不能把清单存在或 agent 审查通过显示成完整形式验证或确认当前仍开放。

用隔离的脚本化 Codex 进程和模拟浏览器响应测试「切换账号」与「退出登录」。核对取消确认时不发出请求，服务端拒绝缺失或为 false 的 `confirm_account_change`，切换会先调用官方退出再启动设备码授权。覆盖成功切换、显式退出、退出后取消新授权和新登录失败；后两种情况应保持模拟账号退出，不恢复旧凭据。中英文都应说明工作区登录独立、本地 Codex 登录不变，以及同一账号仍共用订阅额度。

创建包含凭据、配置和会话哨兵文件的模拟个人 `CODEX_HOME`，执行 MathLottery 账号读写、原生研究、旧版结构化调用与后台进程。检查每个 Codex 子进程都接收工作区独立的 `.mathlottery/codex-home`，并强制使用文件凭据存储；所有操作都不得修改或复制哨兵文件。核对父进程环境保持原样、目录仅当前用户可访问、不同工作区使用不同目录，以及个人会话在独立目录中不存在时不会回退。除初次调用外，也要检查会话元数据与续接路径。

检查当前工作区有 Codex 后台任务运行或 CLI 持有运行锁时，账号变更会在发出退出 RPC 之前被拒绝；任务停止后应允许操作。独立的本地 IDE 客户端使用另一份存储。

除非账户所有者明确选择改变登录，真实账号检查保持只读。模拟授权成功仅证明界面和协议行为；真实设备授权需要账户所有者参与，应单独记录。MathLottery 独立目录为空时，即使本地 Codex 已登录，也应显示未登录。可以在原环境只读运行 `codex login status` 确认本地登录仍存在，但它不代表 MathLottery 独立目录的状态。不得读取或记录凭据内容。

## 离线流程

```bash
mathlottery demo
mathlottery demo --case incorrect
mathlottery demo --case hidden-assumption
mathlottery demo --case finite-only
```

这些案例覆盖正确证明、除零、遗漏假设和用有限测试代替一般证明。Demo 的审查内容是固定测试素材，不代表模型自动识别任意数学错误的能力。

## 真实 Codex 集成检查

先完成 [Codex 配置与工作区登录](configuration.cn.md)，再用 `mathlottery doctor` 检查可执行文件、ChatGPT 登录及本地工具。诊断输出供本机排查使用，不应复制进公开文档。

导入教育示例，并在明确预算下执行：

```bash
mathlottery add --file examples/odd_sum.problem.json
mathlottery solve --backend codex --problem odd-sum --budget-time 3m --max-iterations 5
```

使用命令输出的运行 ID 查看报告：

```bash
mathlottery status <run-id>
mathlottery report <run-id> --show
```

检查候选证明是否保存，以及模型、工具调用和 token 用量是否来自实际运行记录。solve 本身不启动审查。使用该任务的候选单独验证：

```bash
mathlottery verify --backend codex --from-run <solve-run-id> --budget-time 3m
```

检查审查是否使用独立会话，且没有继承原求解轨迹。LLM 审查通过最多为 SELF_CHECKED，不能据此宣称形式证明。

进一步检查同一研究会话的续接：

```bash
mathlottery resume <run-id> --message '检查 n=0 的边界情况，并保留已有研究结果' --budget-time 6m --max-iterations 10
```

预算参数是新的总上限。比较续接前后的研究会话 ID，确认文件仍可读取。原生 Shell、网页搜索和工作区写入边界可以在受控集成任务中单独检查；不要绕过沙箱来使检查通过。

报告和原始事件位于 runs/<run-id>/，数据库位于 .mathlottery/，都属于本机产物，不纳入仓库。真实调用会使用账户的订阅额度，结果和用量不要求逐字复现。

## 验证边界

真实 Chat API 检查需要先配置 API Key 和模型，方法见[接入配置](configuration.cn.md)。选择 `chat` 并设置可用的 API 模型后再运行上述示例，用 `find` 检查选题结果和状态证据。Codex 的模型 ID 或思考选项不一定适用于 API。自动化 HTTP 合约测试不等同于真实账户已具备模型、搜索或代码执行权限。

历史集成检查已覆盖原生 Shell、文件保留、精确会话续接、网页搜索以及候选提交与独立审查。它们证明执行链路可用，不构成与 ChatGPT Pro 或原生 Codex 的数学能力对照评测，也不代表解决了开放猜想。

Lean 等可选工具需要另外安装。缺少工具或外部证据时应如实记录不可用或未验证，不能将其计为通过。

## 本地实验审计

每次 Codex 审计在项目根目录的 `audits/codex_audits/<时间戳>/` 下独立进行，审计脚本、日志、中英文报告和 JSON 摘要集中存放在对应文件夹。新文件夹使用 `YYYY-MM-DD_HH-MM-SS` 命名；仅知道日期的历史报告可使用 `YYYY-MM-DD`。整个 `audits/` 目录由 Git 忽略。公开文档引用可复用的方法和整理后的展示证据。[图论流程脚本](../scripts/experiment_graph_pipeline.py)可作为后续集成实验的复现起点。

## 展示样本的证据

[结果样本](../showcase/README.cn.md)提供各案例的普通证明、审查摘要、验证元数据和复现说明。这些记录分别说明公开来源、开放状态、数学正确性和新颖性。

网格模式案例只有部分 Lean 验证，中位三角形案例已有完整形式陈述通过检查，图论案例则以可执行有限证书辅助其书面反例证明。理解检查通过的含义时，应先阅读各案例注明的范围。
