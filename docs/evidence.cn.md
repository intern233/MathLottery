# 证据、完整性与独立核查

[English](evidence.md) | 简体中文

[使用说明](usage.cn.md) · [资源需求](resources.cn.md) · [成果样本](../showcase/README.cn.md)

MathLottery 分开记录四个问题：**来源是否支持“仍未解决”的判断、候选证明是否有支持、是否覆盖完整原题、文献比较能支持怎样的新颖性结论？** 任务完成不会自动给这些问题作出肯定回答。

## 找题：从网址清单到可核对的证据

选题结果提供 `citations`：网址、来源角色、简短原文摘录、具体位置、已知的来源日期和相关性说明。来源角色区分原题、明确未解状态、后续解答、勘误和已有结果。`literature_search` 保存实际搜索词和检索范围结论。其中 `unresolved` 记录实质缺口，例如无法取得某篇可能的解答、尚未核清的等价关系；`limitations` 单独记录一般检索局限，例如覆盖的数据库、语言、日期，以及可能存在未收录文献。两者都会显示在前端和报告中。不能为了得到肯定状态，把具体未核清来源或比较移入 `limitations`；历史 `unresolved` 条目不会被自动重新分类。

摘录必须保留原文文字。把印刷公式改写成 LaTeX、补上下标下划线、翻译或转述后放入摘录，都可能无法精确匹配；这些内容应写入 `statement` 或 `explanation`。PDF 提取丢失关键公式时，优先引用可访问的原始 HTML/文本版本。必需摘录无法取得或未匹配，仍然是证据缺口，即使 agent 自称读过 PDF。

系统独立下载被引用的公开来源，遵守 robots 策略与大小限制，保存原始字节和提取文本，并在 Unicode/空白规范化后核对摘录。对于 PDF，还兼容数学标点周围的空白及两种已知的倾斜不等号提取别名，并在回执中记录匹配方式；保留词边界、数字、运算符和量词。回执记录 SHA-256、抓取时间、请求网址和实际重定向网址；不会自动认定不同论文版本等价，也不接受模型自填的回执元数据。PDF 提取需要研究依赖，运行在已有 Python 沙箱中，限制为 100 页、512 MB、最多 10 秒和 100,000 个输出字符；提取失败会留下缺口。

保留 `OPEN` 需要核对原题摘录、明确未解的来源、与申报搜索词匹配的实际搜索记录，且不能有实质未解决的文献缺口或后续解答/勘误冲突。所引已有结果与原题关系不明，也会阻止该状态。一般检索局限随有范围的判断一同披露，不能覆盖失败的检查。快照的新鲜度上限是七天，指抓取时间，不是论文发表时间。一个维护中的原始来源可以满足这些可追溯性要求，两个无关域名不能。已核对的未解状态与等价解答冲突时记为 `DISPUTED`；其他证据不足的断言降为 `UNKNOWN`，列明原因。原始选题判断仍保留在运行产物中。

这些是**证据要求，不是“世界上没有解答”的认证**。原文解释、搜索覆盖和命题比较仍由 agent 完成。来源可能有误或过期，搜索可能漏掉不同术语或未收录论文。原生联网工具和 structured 搜索工具暴露的查询会被记录；只有 shell 搜索、没有对应搜索工具回执时，仍会显示覆盖缺口。agent 用 shell 下载的引用来源，可以通过独立下载器重新核对。

原生 Codex 回合因时间或用量限制中断时，已确认会话中成功完成的搜索仍保留原始观察时间。续接时没有再次搜索，不会抹掉这些回执，也不会刷新它们的日期。未完成、失败、取消或会话未确认的搜索不计入；中断回合尚未完成的阶段成果也不会被接收。旧版已经缺失的回执不会被静默补造。

## 求解与验真：明确到底证明了什么

候选声明 `scope`（`COMPLETE`、`PARTIAL`、`COUNTEREXAMPLE`、`UNKNOWN`）和 `remaining_obligations`。这些字段与命题、证明、假设、引用一样不可变。如果归约后的问题尚未解决，完整的归约也只是原题的部分进展。

独立审查提供 `checks`：检查的命题、方法、结果、推导、证据，以及该检查是否为候选证明必需。肯定结论必须有实质推导、反例或独立检查的形式化结果支持。空泛通过、只有有限测试、自称 Lean 已通过、关键步骤仍未解决，都会记为 `INCONCLUSIVE`；具体矛盾检查阻止通过。这让审查可以被复查，但不能保证模型推导永远正确。

`original_problem_coverage` 单独记录 `FULL`、`PARTIAL`、`DIFFERENT` 或 `UNKNOWN`，并比较假设和量词。有未完成义务或候选自述部分成果时，不能记为 `FULL`。部分结论可能正确并保留 `SELF_CHECKED`，原题却仍未解决。完整覆盖明确属于**审查者判断**，不是外部认证。完整流程根据经过证据规则处理的结论决定是否回到求解；独立 verify 即使无法判定也会结束并保存缺口。

新颖性需要最相关已有结果的核对摘录、明确命题比较和实际搜索覆盖。`SPECIAL_CASE` 指候选可由已有定理限制条件直接推出，会与“新成果”冲突；如果旧结果只证明更强候选的一部分，应标为 `DIFFERENT` 并解释新增内容。等价已有结果同样阻止声称新颖性。只有比较证据充分且没有未解决缺口，才保留 `POTENTIALLY_NEW`；它始终不等于“已证明首次发现”。证明正确性不要求新颖性结论为肯定。

找题和验真都应使用 `ORIGINAL_STATEMENT` 标记提出猜想的论文，使用 `EXPLICIT_OPEN` 标记明确说明尚未解决的来源。与既有猜想相同不等于已有证明。`PRIOR_RESULT` 和 `SOLUTION` 应用于已经成立的结果；它们的 `EQUIVALENT` 关系表示候选已被前人证明。引用类型及其解释会保留供核查。

## 监督意见与共享证明留言板

[监督式 Solve](solve-teams.cn.md)在独立 Verify 之前增加研究内部的审核。留言板保存
精确的定理陈述、假设、逐步推导、依赖和冻结材料引用。结构校验拒绝缺失或循环的前提，
但不能据此证明某步数学推导成立。

监督意见绑定内容哈希、已检查步骤和前提审核版本。未回应的质疑、撤回或前提审核变化
都会要求复查。`supervisor_accepted` 是可能出错的研究判断，不是 `FORMAL_VERIFIED`、
专家认证或新颖性证据。认可完整候选还需核对原题范围和剩余义务，但这些意见单独保存，
不写入 `candidate.reviews`；独立 Verify 仍需针对所选版本提供自己的检查及证明附件。

Solve 最终总结同时记录部分成果、未解决和完整解答声称；它不是 Organize 报告，
不会跳过单独的 Verify/Organize。旧 showcase 记录也不会因代码更新而自动获得监督证据。

## 逐项覆盖与可跟进的文献障碍

新版审查提供 `proof_steps` 依赖图：每个关键引理、归约、必要分支和最终结论有固定编号，并关联具名 `checks`。控制器重新计算 `proof_coverage`；依赖缺失、循环依赖、检查编号不存在、只有有限测试或必要步骤仍未解决，都不能获得肯定证明结论。`FORMAL` 检查还需指定 `formal_declarations`，只有绑定当前候选的独立回执中对应的定理声明才能支持该步。这检查提交论证的可追溯性，不能保证审阅者已经识别全部数学上必要的步骤。

声称 `FULL` 覆盖原题，还需提供六类 `statement_alignment`：定义、假设、量词、取值范围、边界情况和结论，逐项写明原题与候选表述、比较理由以及有支撑的检查编号。无关 Lean 定理不能认证原题。命题对齐仍是审阅者判断，控制器不会认证自然语言与形式命题等价。

`literature_search.obstacles` 为每个具体障碍保留固定编号、对应来源、影响和下一步动作；`comparisons` 并列比较已有结果与候选的假设和结论。`RESOLVED` 只是提交的处理结论：必须有当前独立抓取的原文摘录，以及适用时有来源支持的定理比较。不能通过改名或不再提及旧障碍来消除它。旧 `unresolved` 文本需通过 `resolves_legacy_gaps` 明确关联，并通过同样的证据检查。对已保存候选新建 Verify 时也会带上旧文献障碍，不复制之前的审阅结论或会话。

新的来源核查会为**精确网址、原文位置和摘录哈希**建立持久障碍。后来取得当前、匹配该目标的独立回执时，即使继承的 agent 勾选状态仍是 `OPEN`，控制器也能关闭这个访问/摘录障碍；同一论文里的另一句话不能替代它。这只说明原文已经取得并匹配，不认证数学解释。没有登记精确目标的旧自由文本障碍仍需明确解释并提供证据。如果旧摘录写错，需要说明修正并附上同一登记位置的已核对引文；记录会区分这种明确修正和原摘录匹配。

缺失或不受支持的定理比较同样保留自动生成的编号。关闭它需要提交同一来源和位置的受支持比较，并通过 `obstacle_ids` 关联；仅下载论文不够。只有当前独立回执实际记录原网址到目标网址的重定向，才允许据此关联原来源与镜像。相似标题、自述镜像或不同论文版本不会被自动认定等价。

每次新评估保留有效状态、提交状态、关闭依据，以及相对前次控制器评估的变化：新增、已解决、重新打开或未变化。当前证据缺失或过期，会重新打开此前受支持的关闭结论。旧审阅、失败回执和历史缺口文本继续保留，不会在新尝试成功后被覆盖。证据规则版本标明新评估使用了哪套规则；关闭障碍不会自动升级新颖性或证明状态。

障碍的 `evidence_urls` 中，每个网址都需要对应的 citation 和核实过的摘录。可选书目链接应放在 `references`；没有对应引文的论文介绍页不能用于解除障碍。原生搜索工具能读到网页，也不保证独立抓取成功；访问失败仍须保留为明确缺口。

前端可展开**关键证明步骤**及**新颖性待核查事项**。在空闲的 Find 或 Verify 中点击**继续核查这一项**，会填写该障碍的续接方向；核对总预算后，点击**继续研究**才会执行，不会在填表时调用模型。无法获取的来源继续保留为缺口。所有已记录障碍解决，也不等于文献已穷尽或新颖性已证明。

## 独立 Lean 执行记录

在前端验真已有候选时，选择需要的小型证明源文件。系统在审查前冻结文件并计算哈希。

工作区内的 Lean 源码和项目文件可供选择。保存在 `workspace/proof/` 或 `workspace/formal/` 下的小型 Markdown/文本证明、JSON/CSV 证书和 Python 复现脚本也可附带。系统只复制显式选择的文件；脚本是不可信输入，不会被自动执行。所有附件继续受文件数量、字节大小和链接限制；编译产物与依赖缓存不在选择范围内。

审查者可提交请求：

```json
{
  "formal_check": {
    "files": ["workspace/Lemmas.lean", "workspace/Main.lean"],
    "declarations": ["Main.target"]
  }
}
```

文件必须来自附件清单，按依赖顺序列出，使用普通模块名；定理必须在提交模块中定义。检查器在无网络的 bubblewrap 沙箱中编译冻结字节，只接收预期的普通目标文件，再用 `leanchecker` 重放提交模块。系统维护的检查程序在禁用模块初始化和扩展载入的情况下读取定理类型和传递公理依赖。选中定理仅允许依赖 `propext`、`Classical.choice`、`Quot.sound`；依赖 `sorryAx` 或自定义公理不能通过。其他位置未被目标定理使用的占位符不等于该定理未证明，请以记录的检查范围为准。

可选的 `module_root` 默认为提交的工作区。如果 `workspace/proof/Main.lean` 通过 `import Lemmas` 导入同目录的 `workspace/proof/Lemmas.lean`，请设置 `"module_root": "proof"`，并按依赖顺序附加这两个文件。若使用 `import proof.Lemmas`，则保留空根目录。根目录必须是普通相对目录，所有请求文件都必须位于其中。它只改变模块解析方式，不改写源码字节、不读取未附加文件，也不允许提交模块替换受信库或检查器。回执保留原始源码路径，并记录对应的模块名。

回执记录原题哈希、候选哈希、源码/目标文件哈希、编译器版本、命令、退出码、资源限制、日志、定理类型和公理。`KERNEL_REPLAYED` 可以支持 `PARTIALLY_VERIFIED`，不会自动产生 `FORMALLY_VERIFIED`、`EXPERT_REVIEWED` 或“原题已解决”。预编译依赖、编译器和 Lean 自身内核仍属于信任基础；这里没有使用另一套独立内核实现，自然语言与形式命题的等价性也仍需审查。

检查达到资源上限时，可以继续原 Verify 并要求重试。在可展开的**独立 Lean 检查资源**中调整该任务的 Lean 内存阈值、虚拟地址空间上限和形式检查总时限；留空保留已保存的值。新尝试保留此前的失败回执，并继续检查同一份冻结源码。独立来源/形式检查期间，动态页会保留已保存的研究回复，并显示证据检查尚未完成。

继续原生审阅时，agent 会收到本次审阅的控制器来源评估、校验说明及匹配候选哈希的形式回执，以便根据完成后的检查重新判断。候选未变时可以复用成功回执，无需重复编译。这份反馈不包含之前 agent 的观点或求解历史；新建 Verify 仍会独立审阅，不继承这些旧结果。

检查器不执行提交的 Lake 配置，不下载依赖，不构建 mathlib。请另行安装兼容的 Lean、`leanchecker`、bubblewrap 和 `prlimit`（Linux/WSL）。环境禁止 bubblewrap 命名空间时会报告失败，不回退到无限制执行。先准备兼容的预编译依赖，然后在 `config.yaml` 配置：

```yaml
verification:
  fetch_sources: true
  max_sources: 12
  source_timeout_seconds: 60
  formal_enabled: true
  lean_command: lean
  lean_library_paths: []  # 预编译库目录，路径相对于项目根目录。
  formal_timeout_seconds: 120
  formal_memory_mb: 2048
  formal_address_space_mb: 8192
  formal_max_object_mb: 16
  formal_max_total_object_mb: 960
```

例如，一个准备好的 Lean 项目可能需要自身 `.lake/build/lib/lean` 及各依赖的对应构建目录；它们必须与编译器版本匹配。使用自己的本地配置，程序不会自动发现并写入机器专用路径。回执检查程序用 Lean 4.35.0 实测；工具链不兼容时必须报告失败，不能静默跳过检查。

编译对象另有大小限制：`formal_max_object_mb` 默认每个文件 16 MiB，由 `RLIMIT_FSIZE` 限制；`formal_max_total_object_mb` 默认总共 960 MiB。编译期间会监测输出总大小，并在接受前重新检查；这不是整台机器的磁盘配额。临时输出最多包含 256 个文件/目录条目，只有预期的普通目标文件可以进入重放与检查。较短的源码也可能生成很大的证明对象，需要时可根据实测结果调整本地限额。较大型证明可将 `formal_timeout_seconds` 配置到最多 1,800 秒，仍与任务共享剩余时间预算。回执保存限额、对象大小和哈希；检查结束后删除临时编译对象，保留运行目录中的回执和日志。

默认每次选题/审查阶段成果最多独立抓取 12 个网址。下载在请求/数据块之间检查时间预算和停止信号；正在等待的请求仍可能持续到 `tools.web_timeout_seconds`，活动时间会计入总预算。`backend.native_network_access: false` 也会禁用独立下载。形式检查共享剩余任务时间，采用一个 Lean 工作线程、64 MiB 线程栈，默认同时施加 2,048 MB 的 Lean `-M` 阈值，以及独立的 8,192 MB 每进程虚拟地址空间限制（`RLIMIT_AS`）。预留栈与映射库占用地址空间，8 GiB 上限不是已分配 RAM，也不是实测峰值 RSS。分开的上限用于容纳 [Lean 启动阶段的栈预留](https://github.com/leanprover/lean4/blob/v4.35.0/src/runtime/thread.cpp)。它们**不是对原生 agent 命令、整个子进程树、WSL 或 Windows 的全局 RSS 上限**。超时或资源失败表示检查未完成，不表示数学命题为假。增加限制前请看[资源说明](resources.cn.md)。

## 前端、报告与历史兼容

前端和 Markdown 报告分别显示候选范围、原题覆盖、尚待证明事项、具体检查、文献缺口和独立形式检查回执。规则修改了结论时，新记录保留原始 agent 结论与新颖性判断。旧检查点继续可读，原有结论不被静默重写；缺少新增证据时显示“尚未按新证据规则评估”。需要新版判断时，重新执行一次 verify。

来源与执行回执保存在被忽略的运行目录 `literature/` 和 `verification/`；开发审计放在被忽略的 `audits/codex_audits/<timestamp>/`。精选[成果样本](../showcase/README.cn.md)继续使用各自明确记录的历史验证范围。

已完成的原生网页搜索及可识别 MCP 搜索调用都可提供查询记录，查询来自工具输入，不来自 agent 自述。失败调用和任意 Shell 输出不计作检索回执。MCP 回执仍需结合独立抓取的原始来源摘录，不会自动认证新颖性。
