# Solve 多组研究

[English](solve-teams.md) · [使用说明](usage.cn.md)

在页面打开 **Solve → 预算与 agent 设置**，设置**求解并行数**，并按需设置
**最大研究组数**。并行数限制所有组同时运行的研究者总数，包含互检；组数限制同时启用
的研究组。例如并行数 6、最大组数 2，可以分成两组各 3 人，也可以只开一组、最多 6 人。
两者都是上限，不要求占满。监督调用单独计开销，不占研究组名额。
设置仅作用于当前任务；共用后端时，可在停止后，通过续接表单修改下一次执行的两个上限。

要给各研究者分配不同的 Codex 账号、Codex API Key 或独立 Responses API 接入，先打开独立的 **Agent 配置**页（`/agents`），再在 Solve 勾选**使用已配置的 agent 槽位**。见[槽位配置说明](agents.cn.md)。重新分组时，各槽位保留自己的接入与会话。槽位 1 还承担研究轮次开始前的监督和研究结束后的收尾。有明确槽位配置的任务在续跑时保持原配置；更换接入或数量需要新建任务。

CLI 新任务可以直接修改项目配置：

```yaml
solve:
  parallel_agents: 6
  max_groups: 2
  supervisor_timeout_seconds: 120
```

也可以使用 `mathlottery solve --problem <problem-id> --parallel-agents 6 --max-groups 2`。
已有任务可用 `mathlottery resume <run-id> --max-groups 1` 修改组数上限。

`max_groups` 支持 1–32，需要同时明确设置 `parallel_agents`；为 `null` 时只受研究者
总并行数限制。每组至少需要一个研究者，因此实际组数上限取两个上限的较小值。
这里限制的是同时启用的组数，不是历史累计创建组数；缩减上限会保留停用组的会话与成果。
前端留空沿用配置或该任务保存的值。

`parallel_agents` 的含义：

- `null` 是兼容默认值，保留原来的原生委派设置。
- `1` 沿用单个持续研究会话，不额外调用监督者。
- `2`–`32` 启用监督分组；这是上限，不要求始终占满。
- 当前仅为 Codex 或 Chat/Responses 的**独立原生 solve**提供此调度器。
  组合命令 `run`、其他步骤和 manual/structured 模式不使用该调度器。
  页面会拒绝给其他步骤指定求解并行数。

## 调度与上下文

在自然研究回合之间，持续的监督会话读取原题、已记录成果、具体障碍和用量，提出
分组、人数、研究方向及协作模式：独立探索、同级协作、推导与质疑。模式提供研究指导，
不规定每次工具调用，也不要求永久固定专家角色。保留一个连续的主研究会话；暂时未分配
名额的研究者，其会话与文件仍然保留。

调度器同时验证人数和组数上限。错误的分配不能突破任一上限；监督超时则沿用保存的方案，
并按当前两个上限限制执行，续跑时降低组数也会生效。
扩缩容发生在当前研究者完成自然检查点，或触发现有时间/停止条件之后；**当前不会在
某个原生调用中途调整分组**。监督者也不提供经过校准的数学完成百分比。

明确设置并行数后，会关闭原生嵌套 agent 创建，新增研究者统一向调度器申请，确保不能
绕过并发限制。搜索、命令执行、配置的研究记忆、持续会话与原生压缩仍由接入后端提供。
自检、互检与研究者的声称都属于 Solve 记录，不自动成为独立验证或新颖性认证。

## 跨组留言板

研究者可按工作区的 `board-message.schema.json`，在 `outbox/<唯一编号>.json` 发布
成果、求助、质疑、失败路线、研究意向和撤回。留言包含假设、依赖留言编号和可选的本地
证明源码路径。调度器将留言写入工作区 SQLite，冻结所引用的 UTF-8 文件，并在各研究
工作区生成 `bulletin/` 索引与材料。研究者按需浏览，避免把所有讨论塞进上下文。

作者可以撤回自己的留言；对其他作者的成果使用质疑。依赖受影响成果的留言会标记为
需要重新检查。既有留言不可覆盖，修订须使用新编号并明确引用旧内容。`author_checked`
只是作者自查声明，发布到留言板不等于证明已认证。

引用的每份材料上限为 2 MB，留言 JSON 文件上限为 100 KB；大型实验数据和编译产物
保留在研究工作区。发布失败原因记录于 `bulletin/publication-errors.json`。

Codex 研究者可以在执行中读取新留言。Chat 托管工具无法访问本地文件，因此在检查点
内联收到留言及一定大小的冻结材料，省略的材料会明确列出。**Chat 当前在检查点之间
共享，不提供运行中的实时留言读取。** 完整回答和原始文件仍在本地保存。

## 预算、恢复与观测

研究及监督调用均计入总时间、token 和调用次数限制；页面另列监督用量。发起一轮前会
为并发研究者预留调用次数。Token 限额在调用之间检查，已在运行的并行调用可能在返回
时超出阈值；未知用量保持未知。并行数不是 CPU、内存或费用限制，仍需使用工作区资源
控制及提供方费用限制。

展开「研究者活动」可以分别查看各研究者最近的可见动作及输出；完整活动下载包含
尚未返回的并行调用。这些是实际观测记录，不是隐藏推理或解题成功率。

停止或中断时等待本地研究进程退出。每个研究者独立保存调用回执和会话引用，恢复时
已完成的回执只应用一次；未结束的远端响应需先恢复处理。耗尽时间后，原有的有界收尾
调用可以汇总已保存成果。完整候选仍然只是求解者声称。Find、独立 Verify、Organize
保留各自行为。

可运行 `pytest -q tests/test_solve_team.py` 检查调度、并发及恢复。测试使用可控的原生
agent 替身，不代表真实模型的数学能力或解题质量。
